## 3. Findings

<a id="g-1"></a>

### G-1 — the B2B draft screens refuse staff members · high (code) · guides annotated

As «مدير المتجر» (who holds both B2B permissions), `/dashboard/orders/b2b` shows «تعذّر تحميل البيانات» with «غير مصرح لك بالوصول.» (`GET /api/v1/orders/b2b-drafts/` → `401`), and the draft form's save is refused the same way (`POST /api/v1/orders/b2b-draft/` → `401` in the API run); the owner sees the list but cannot create a draft («يتطلب إنشاء طلب الجملة تسجيل دخول موظف.»). Cause and code fix: [`../api/_verification.md`](../api/_verification.md#f-1) (OI-10). **Annotated**: a «قيد معروف» in [`merchant/09-b2b/create-draft.md`](merchant/09-b2b/create-draft.md) and [`merchant/09-b2b/approve-drafts.md`](merchant/09-b2b/approve-drafts.md); the steps themselves stay as written, because they are right once the code is fixed.

<a id="g-2"></a>

### G-2 — an expired cart-restore link shows «غير متاح بعد.» instead of the documented message · medium (code) · guide annotated

`/cart?restore=<bad token>` shows the toast «غير متاح بعد.» and an empty cart: the BFF answers `501` when Django answers `404` «رابط استرداد السلة غير صالح أو انتهت صلاحيته.» ([`../api/_verification.md`](../api/_verification.md#f-2), OI-21). **Annotated**: a «قيد معروف» in [`buyer/05-storefront/cart-reminders.md`](buyer/05-storefront/cart-reminders.md). The same rule applies to the «المنتج غير موجود.» rows of `wishlist.md` and `back-in-stock.md` (a product hidden after it was saved); that case needs a product hidden mid-session and was not reproduced on screen, so those two pages are not annotated. The tracking page is **not** affected: its server fetcher turns the `404` into the documented «لم نجد هذا الطلب» screen with «تأكد من الرابط الذي وصلك عبر واتساب.» (checked live with an unknown uuid).

<a id="g-3"></a>

### G-3 — two development-only hydration warnings · low · logged

`next dev` reported React hydration mismatches on `/cart?restore=…` (the server renders the skeleton list, the client the empty-cart block) and once on the console overview (a skeleton vs a figure). They are development warnings (the tree is re-rendered on the client) and nothing a guide reader sees; recorded for the frontend team, no guide change.

<a id="g-4"></a>

### G-4 — the walkthrough is scripted · process

The walk proves that every screen a guide names opens for its audience, live, in RTL, with valid data shapes and the quoted sentences present in the code. It does not prove that a person following the numbered steps reaches the described result on every page; that is what fares's sign-off column records (all rows signed off on 2026-10-30). Pages with a ⚠️ visit are the ones to read first.
