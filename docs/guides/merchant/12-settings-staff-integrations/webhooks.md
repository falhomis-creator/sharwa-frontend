# Webhooks: إرسال أحداث متجرك إلى أنظمتك

> **المصدر**: DOC-396 · INT-023 (M19) · الجرد: المجال 12 · آخر مراجعة على الكود: 2026-10-28 (الخطوة 35)

«أرسل أحداث متجرك (الطلبات، الشحن، المخزون) إلى أنظمتك الخاصة فور حدوثها.» نقطة النهاية عنوان على خادمك يستقبل طلباً موقَّعاً كلما وقع حدث اخترته. هذه الصفحة لمالك المتجر؛ تفاصيل الاستقبال والتحقق من التوقيع لمطوّرك في [صفحة المطوّرين](../../../api/integrators/webhooks-outgoing.md). المصطلحات في [مسرد الأدلة](../../_glossary.md).

## لمن هذه الصفحة؟

| | |
|---|---|
| **الجمهور** | مالك المتجر، ومطوّره |
| **الصلاحية المطلوبة** | لا مفتاح صلاحية؛ للمالك وحده: «الـ Webhooks مقصورة على مالك المتجر.» |
| **ميزة الباقة** | لا توجد |
| **لمالك المتجر فقط؟** | نعم |
| **مكانها** | «الإعدادات» ← «Webhooks» (`/dashboard/settings/webhooks`)، ونقطة النهاية (`/dashboard/settings/webhooks/<رقمها>`) |

## الأحداث

| الحدث | اسمه | متى يُرسل |
|---|---|---|
| `order.created` | «طلب جديد» | «عند إنشاء طلب من المتجر أو الكاشير أو القنوات.» |
| `order.status_changed` | «تغيّر حالة الطلب» | «عند نقل الطلب إلى حالة جديدة.» |
| `order.fulfillment_changed` | «تغيّر حالة التجهيز» | «عند تغيّر التجهيز أو الشحن للطلب.» |
| `order.refunded` | «استرداد طلب» | «عند استرداد كامل أو جزئي لمبلغ طلب.» |
| `shipment.event` | «حدث شحنة» | «كل تحديث تتبع مقبول على بوليصة.» |
| `product.updated` | «تحديث منتج» | «عند تعديل السعر أو البيانات أو الظهور.» تغيير الكمية وحدها لا يرسله |
| `inventory.low_stock` | «مخزون منخفض» | «عند وصول كمية منتج إلى حد التنبيه.» مرة واحدة كلما دخل المنتج حد التنبيه |

## الخطوات

### إضافة نقطة نهاية

1. اضغط «إضافة نقطة نهاية». تفتح «نقطة نهاية جديدة»: «اختر الأحداث التي تريد استقبالها. نعرض لك سرّ التوقيع مرة واحدة بعد الإنشاء.»
2. اكتب «عنوان نقطة النهاية»: «https فقط. نرسل إليه طلب POST بحمولة JSON موقَّعة بالسرّ.»
3. اختر «الأحداث» (واحد على الأقل).
4. اكتب «الوصف» إن أردت: «اختياري — لتتذكر الغرض منها.»
5. اترك «مفعّلة» مشغّلاً: «عند الإيقاف لا نرسل إليها أي حدث.»
6. اضغط «إنشاء نقطة النهاية».
7. تظهر «سرّ التوقيع»: «انسخه الآن واحفظه في نظامك — لن يُعرض مجدداً. نستخدمه لتوقيع كل طلب في الترويسة» `X-Sharwa-Signature`. السرّ يبدأ بـ `whsec_`. انسخه ثم اضغط «نسخته، أغلق».

### القائمة

| العمود | معناه |
|---|---|
| «العنوان» | عنوان نقطة النهاية ووصفها |
| «الأحداث» | عدد الأحداث المختارة |
| «الحالة» | «مفعّلة» أو «موقوفة» أو «معطّلة تلقائياً» |
| «آخر تسليم» | نتيجة آخر إرسال ووقته، أو «لا تسليم بعد» |
| «إخفاقات متتالية» | عدد الإخفاقات منذ آخر نجاح |

![قائمة «Webhooks»](../../_assets/merchant/12-settings-staff-integrations/webhooks-2.png) <!-- capture: /dashboard/settings/webhooks, desktop 1440, mock mode -->

### صفحة نقطة النهاية

- «تعديل» يفتح «تعديل نقطة النهاية»: «السرّ لا يتغير بالتعديل — استخدم «تدوير السرّ» لذلك.» اضغط «حفظ التغييرات»: «حُفظت نقطة النهاية»
- «إيقاف» أو «تفعيل».
- «سرّ التوقيع»: «محفوظ ومخفي — لا يُعرض مجدداً».
- «حذف نقطة النهاية» يسأل «حذف نقطة النهاية؟»: «لن نرسل إليها أي حدث بعد الآن، ويُحذف سجل تسليمها.»

### إرسال حدث تجريبي

يرسل حمولة اختبار `webhook.test` «لتتأكد أن نظامك يستقبل ويتحقق من التوقيع.»

1. اضغط «إرسال حدث تجريبي».
2. تظهر النتيجة: «وصل الحدث التجريبي» أو «فشل الحدث التجريبي»، مع رمز الاستجابة والمدة.

يُرسل الحدث التجريبي حتى لو كانت نقطة النهاية موقوفة، فتختبرها قبل تفعيلها.

### تدوير السرّ

1. اضغط «تدوير السرّ». تسأل «تدوير السرّ؟»: «سيتوقف السرّ الحالي فوراً، وسيرفض نظامك الخارجي كل التوقيعات حتى تحدّثه بالسرّ الجديد. لا يمكن التراجع.»
2. اضغط «تدوير السرّ». يظهر «السرّ الجديد» مرة واحدة. انسخه وحدّث نظامك فوراً.

إن أغلقت نافذة السرّ دون نسخه: «أُغلق السرّ — استخدم «تدوير السرّ» إن فقدته».

### سجل التسليم

«سجل التسليم» في صفحة نقطة النهاية: كل محاولة إرسال، الأحدث أولاً.

| العمود | معناه |
|---|---|
| «الحدث» | اسم الحدث، أو «حدث تجريبي» |
| «الوقت» | وقت المحاولة |
| «الحالة» | «قيد الإرسال» أو «سُلِّم» أو «فشل» |
| «رمز الاستجابة» | رمز HTTP من خادمك، أو «—» |
| «المدة (ms)» | زمن المحاولة |
| «المحاولة» | 1 للإرسال الأول، ثم 2 و3… |

- الفلاتر: «الحالة» و«الحدث» و«من» و«إلى».
- **إعادة إرسال المحاولة الفاشلة:** اضغط «إعادة الإرسال» في صفها. تُكتب محاولة جديدة برقم أكبر، وتبقى القديمة في السجل: «أُعيد الإرسال — سُلِّم ((الرمز))» أو «أُعيد الإرسال وفشل مجدداً ((الرمز))».

![«سجل التسليم»](../../_assets/merchant/12-settings-staff-integrations/webhooks-3.png) <!-- capture: /dashboard/settings/webhooks/1, desktop 1440, mock mode -->

## ما يحدث بعد ذلك

- **التوقيع:** كل طلب يحمل الترويسة `X-Sharwa-Signature` بصيغة `t=<وقت>,v1=<توقيع>`. التوقيع HMAC-SHA256 بالسرّ على الوقت ونص الطلب. طريقة التحقق لمطوّرك في [التحقق من التوقيع](../../../api/integrators/webhooks-verify-samples.md).
- **المحاولات التلقائية:** إن فشل الإرسال يُعاد بعد دقيقة، ثم بعد 5 دقائق: 3 محاولات في المجموع.
- **التعطيل التلقائي:** بعد **10** إخفاقات متتالية تصبح نقطة النهاية «معطّلة تلقائياً» ولا يُرسل إليها شيء: «عُطّلت بعد (العدد) إخفاقات متتالية. أصلح الخادم ثم أعد التفعيل.»
- **إعادة التفعيل:** اضغط «إعادة التفعيل». يظهر «أُعيد تفعيل نقطة النهاية»، ويعود عدّاد الإخفاقات إلى صفر.
- أي نجاح يعيد العدّاد إلى صفر.
- إن فشل إرسال الحدث لا يتأثر الطلب أو العملية في متجرك.

## الرسائل التي قد تظهر لك

| الرسالة | السبب | ماذا تفعل |
|---|---|---|
| «أدخل عنوان نقطة النهاية.» | العنوان فارغ | اكتبه. |
| «العنوان يجب أن يبدأ بـ https://» | العنوان `http` | استخدم `https`. |
| «لا تُقبل العناوين الداخلية — استخدم عنواناً عاماً.» | عنوان داخلي أو محلي | استخدم عنواناً عاماً على الإنترنت. |
| «عنوان غير صالح.» | العنوان غير صحيح أو أطول من 500 حرف | صحّحه. |
| «اختر حدثاً واحداً على الأقل.» | لا أحداث | اختر حدثاً. |
| «أحداث غير معروفة: (الأحداث)» | حدث غير موجود | حدّث الصفحة. |
| «200 حرف كحد أقصى.» | الوصف طويل | اختصره. |
| «هذا العنوان مضاف بالفعل.» | العنوان مستخدم في نقطة أخرى | عدّل النقطة الموجودة. |
| «الحد الأقصى 10 نقاط نهاية لكل متجر.» | 10 نقاط | احذف نقطة لا تستخدمها. |
| «نقطة النهاية غير موجودة.» | حُذفت | ارجع إلى القائمة. |
| «إعادة الإرسال للتسليمات الفاشلة فقط.» · «التسليم غير موجود.» | المحاولة ليست فاشلة أو حُذفت | حدّث الصفحة. |
| «تعذّر الوصول للعنوان أو أنه عنوان داخلي.» | خطأ في سجل التسليم: العنوان لا يصل أو صار داخلياً | تحقّق من الخادم وعنوانه. |
| «انتهت مهلة الاستجابة.» | خادمك لم يجب خلال 10 ثوانٍ | سرّع الاستجابة: أجب بـ 2xx ثم عالج لاحقاً. |
| «نقطة النهاية معطّلة.» | توقفت نقطة النهاية قبل الإرسال | فعّلها. |

## حدود يجب معرفتها

- 10 نقاط نهاية لكل متجر.
- السرّ يُعرض مرة واحدة: عند الإنشاء وعند التدوير.
- النجاح = أي رمز 2xx. لا تُتبع التحويلات (3xx).
- إعادة التفعيل تصفّر العدّاد في كل مرة تشغّل فيها نقطة موقوفة، لا بعد التعطيل التلقائي وحده.

## قيود معروفة

> **قيد معروف:** تقول شاشة «Webhooks» «ونعيد المحاولة للفاشلة حتى 5 مرات»، والمتجر يحاول 3 مرات في المجموع.

> **قيد معروف:** «إعادة الإرسال» تعمل حتى لو كانت نقطة النهاية موقوفة، وكل إعادة فاشلة تزيد عدّاد الإخفاقات.
