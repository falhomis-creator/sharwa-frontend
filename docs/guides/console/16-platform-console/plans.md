# الباقات ومصفوفة الميزات

> **المصدر**: DOC-441 · INT-032 (M46) · الجرد: المجال 16 · آخر مراجعة على الكود: 2026-10-28 (الخطوة 42)

«الباقات» تحدد سعر الاشتراك وحدوده وعمولة المبيعات، و«مصفوفة الميزات» تحدد أي ميزة تتيحها كل باقة. الكتابة للمالك؛ «مشرف تشغيلي» يرى للقراءة فقط.

## لمن هذه الصفحة؟

| | |
|---|---|
| **الجمهور** | «مالك المنصة» (كتابة) و«مشرف تشغيلي» (قراءة) |
| **الحساب المطلوب** | «مالك المنصة» (`superuser`) للكتابة |
| **ميزة الباقة** | لا تنطبق — هذه الشاشات مصدر نظام الباقات نفسه |
| **للمالك وحده؟** | الكتابة للمالك |
| **مكانها** | «الباقات والميزات» ← «الباقات» (`/plans`) و«مصفوفة الميزات» (`/plans/matrix`) |

## قائمة الباقات

جدول: الكود، الاسم، السعر، الفترة («شهري»/«سنوي»/«مدى الحياة»)، **العمولة**، حد المنتجات، حد الطلبات/شهر، «افتراضية مجانية»، الحالة، الترتيب، و«اشتراكات حالية» (رقم يفتح [الاشتراكات](subscriptions-and-billing.md) مفلترة على الباقة والحالية فقط).

عرض العمولة بثلاث صور كما يرسلها الخادم: «—» بلا عمولة، أو «2.50%» نسبة، أو مبلغ مثل «3 ر.س». القيم الظاهرة هي المسجَّلة لحظة البيع (نسخة داخل كل سجل عمولة) — تغييرها لا يغيّر التاريخ.

## إضافة أو تعديل باقة

«باقة جديدة» أو «تعديل» تفتح لوحة بخصائص نموذج الباقة نفسها («الحقول كما في نموذج Plan — لا حقول إضافية.»):

| الحقل | إلزامي؟ | القيود |
|---|---|---|
| «الكود» | نعم | حروف لاتينية صغيرة وأرقام و `_` (2–30) — «حروف لاتينية صغيرة وأرقام و_ (2–30).» **يُقفل بعد الإنشاء**: «الكود ثابت لا يتغيّر بعد الإنشاء — يُستخدم برمجياً.» |
| «الاسم» | نعم | «أدخل اسم الباقة.» |
| «مجانية» | مفتاح | الباقة المجانية سعرها 0: «الباقة المجانية سعرها 0.» |
| «السعر» و«العملة» و«فترة الفوترة» | نعم | سعر صحيح حتى خانتين («أدخل سعراً صحيحاً (مثال: 49.00).») |
| «نوع العمولة» و«قيمة العمولة» | نعم | «بلا عمولة» / «نسبة» / «مبلغ ثابت»؛ النسبة حتى 100: «النسبة 100 على الأكثر.» |
| «حد المنتجات» و«حد الطلبات/شهر» | لا | رقم صحيح أو فارغ — «فارغ = بلا حد» |
| «نشطة» | مفتاح | غير النشطة لا تُسنَد لمتاجر جديدة |
| «الباقة المجانية الافتراضية» | مفتاح | يجب أن تكون مجانية **ونشطة**: «الباقة الافتراضية يجب أن تكون مجانية.» / «الباقة الافتراضية يجب أن تكون نشطة — التسجيل يُسندها للمتاجر الجديدة.» **واحدة فقط** («تُسند للمتاجر الجديدة عند تفعيل الباقات. واحدة فقط.») — تعيين ثانية ينزع العلم عن الأولى تلقائياً |

## حذف باقة

«حذف» ثم نافذة: «تُحذف الباقة وخلاياها في المصفوفة. الباقة التي عليها اشتراكات حالية لا تُحذف.» الرفض صورتان، وتعرضهما اللوحة بإطار أحمر مع زر «نقل إلى باقة أخرى» يفتح [الاشتراكات](subscriptions-and-billing.md) مفلترة:

- عليها اشتراكات **حالية**: «لا يمكن حذف باقة عليها N اشتراكاً حالياً — انقلها إلى باقة أخرى أولاً.»
- عليها اشتراكات **تاريخية** فقط: «الباقة مرتبطة باشتراكات سابقة في سجل المتاجر — عطّلها («غير نشطة») بدل الحذف.» — سجل الاشتراكات محفوظ دائماً ولا يُحذف مع أي باقة.

## مصفوفة الميزات (`/plans/matrix`)

جدول الميزات × الباقات، لكل خلية مفتاح صغير **يُحفظ لحظة تبديله** (لا زر حفظ؛ إن فشل الحفظ تُعاد الخلية كما كانت مع «تعذّر حفظ الخلية — أُعيدت كما كانت.»):

- الميزات التي «تتطلب باقة» هي وحدها المؤثرة هنا؛ ما لا يتطلبها يظهر باهتاً بعبارة «متاحة لكل الباقات — لا أثر للمفاتيح»، والموقوفة عالمياً بعبارة «موقوفة عالمياً».
- أعلى الصفحة إن كانت الباقات معطّلة: «الباقات غير مفعَّلة — كل الميزات ذات requires_plan تُعتبر متاحة.» مع رابط للمفاتيح الرئيسية.

## ما يحدث بعد ذلك

- خلية المصفوفة هي الخطوة الخامسة في ترتيب حسم «هل الميزة متاحة لهذا المتجر؟» (انظر [الاشتراكات والمفاتيح الرئيسية](subscriptions-and-billing.md))؛ غياب الخلية عن الباقة يعني غير متاحة.
- نسبة العمولة تُقرأ من الباقة لحظة كل بيع وتُنسخ داخل سجل العمولة — تعديلها لا يمس المستحقات القائمة.
